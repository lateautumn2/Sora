# 评论回复与客户端一言调整设计

## 目标

调整后台评论回复的操作位置和展开方式，并将一言内容从服务端缓存请求改为前台浏览器按页面访问重新请求。

## 范围

本次包含两项修改：

1. 评论回复按钮与“通过 / 垃圾 / 删除”等状态操作处于同一行；回复编辑区展开后占满评论正文区域。
2. 启用一言时由浏览器直接请求外部 API，不使用服务端缓存；关闭一言时才显示后台填写的页脚文字。

不修改评论回复服务端动作、评论数据结构、站点设置字段或后台设置表单。

## 评论回复交互

`CommentReplyForm` 继续作为客户端组件管理单条评论的展开状态，但不再渲染独立面板容器。组件通过 Fragment 返回回复按钮和条件表单，并放入现有 `.admin-comment-actions` 操作行：

- 回复按钮与状态按钮共同参与 Flex 布局。
- 点击回复按钮时切换展开状态，再次点击同一按钮收起。
- 回复按钮保留 `aria-expanded` 与 `aria-controls`。
- 删除取消按钮。
- 提交按钮文字由“提交回复”改为“提交”。
- 展开的 `.admin-comment-reply` 使用 `flex-basis: 100%` 和 `width: 100%` 换到下一行，占满评论内容区；内部仍为宽文本框加提交按钮的两列布局。
- 手机宽度下表单继续切换为单列，提交按钮位于文本框下方。

## 客户端一言

服务端 `SiteFooter` 只负责读取站点设置，并将 `footerHitokotoEnabled` 与 `footerText` 传给新的客户端组件 `SiteFooterNote`。

`SiteFooterNote` 的行为：

- 一言关闭：直接显示 `footerText`，不发起外部请求。
- 一言开启：初始不显示任何页脚文字。
- 一言开启且请求成功：校验 `hitokoto` 为非空字符串后显示。
- 一言开启但请求失败、HTTP 状态异常或响应无效：保持空白，不显示 `footerText`。
- 使用浏览器 `fetch` 的 `cache: "no-store"`，不复用 HTTP 缓存。
- 监听 `usePathname()`；首次加载和前台路径变化时重新请求，使共享布局中的页脚也能在页面导航后获取新内容。
- 每次请求开始先清空旧内容，并通过 `AbortController` 取消已经失效的请求，避免快速导航时旧响应覆盖新页面。

移除不再使用的服务端 `lib/content/footer-note.ts`，避免保留两套一言请求路径。

## 异常与边界

- 外部 API 不可用不会影响页面其余内容，也不会出现错误提示或静态文字回退。
- 外部 API 可能随机返回与上一次相同的内容；项目保证每次页面路径访问发起新请求，但不人为排除重复句子。
- 同一路径内仅修改客户端局部状态不会触发新请求；完整刷新或导航到其他前台路径会触发。
- 一言关闭时，后台填写的空字符串仍保持不渲染页脚文字。

## 测试与验收

- 评论测试验证回复按钮位于 `.admin-comment-actions` 内，与垃圾、删除按钮同组。
- 评论测试验证首次点击展开、再次点击收起，不存在取消按钮，提交按钮名称为“提交”。
- 评论样式测试验证回复表单占据操作行的完整下一行。
- 页脚测试验证关闭时显示后台文字且不请求。
- 页脚测试验证开启时初始留空、成功后显示一言、失败后仍留空。
- 页脚测试验证路径变化会再次请求，并使用 `cache: "no-store"`。
- 运行专项测试、全量单元测试、类型检查、定向 ESLint 和生产构建。
