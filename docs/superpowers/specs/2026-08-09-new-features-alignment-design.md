# 新增功能全面对齐设计

## 目标

在保留当前新增功能和既有后台改动的前提下，统一搜索、评论环境信息、头像、评论即时回显、数据库迁移及测试之间的接口、交互与视觉表现，并证明项目整体可构建运行。

## 当前新增功能

本轮纳入以下工作区能力：

1. 首页与站点顶部栏的弹窗搜索，以及公开搜索 API。
2. 搜索服务的全角字符规范化、FTS 前缀匹配和普通文本包含匹配。
3. 评论请求上下文，包括客户端 IP、城市、浏览器名称与版本。
4. 评论接口即时返回审核通过的公开评论。
5. 评论提交后即时插入列表、更新计数，并保存访客常用资料。
6. Gravatar 头像及加载失败后的本地首字头像。
7. 第 8 个运行时数据库迁移，为评论增加环境信息字段。
8. 前序后台结构、编辑器、分页器、媒体、友链和页脚一言调整。

## 范围边界

- 不移除或回退用户新增功能。
- 不改变站点设置字段、评论审核策略或搜索结果数量上限。
- 不公开评论邮箱、完整 IP 地址或 User-Agent 原文。
- 不引入新依赖，不进行无关页面重设计。
- 视觉调整沿用当前 Sora 前台设计语言：克制的暖色强调、轻边框、紧凑圆角、衬线标题和等宽辅助信息。

## 搜索功能对齐

### 数据与接口

- `GET /api/v1/public/search` 继续接收 `q`，统一使用 NFKC 规范化并去除首尾空白。
- 空关键词直接返回空数组，不访问数据库。
- 超过 100 个字符返回 `QUERY_TOO_LONG` 与 422。
- 搜索结果只包含公开、已发布且发布时间不晚于当前时间的文章。
- API 只返回弹窗所需字段：`id`、`title`、`slug`、`excerpt`、`publishedAt`。
- 搜索服务同时支持 FTS 前缀匹配和标题、摘要、正文的转义 LIKE 包含匹配；排序优先精确标题、标题包含、FTS 相关度，再按发布时间。

### 前台交互与视觉

- 首页和顶部栏继续复用 `SiteSearch`，避免两套搜索状态。
- 搜索在当前页面弹窗内完成，不跳转到独立搜索页。
- 输入保持 300 毫秒防抖，并在新查询或关闭弹窗时取消旧请求。
- 加载、错误、空结果和结果列表均保留明确状态。
- 搜索框、结果卡片、日期、空态和移动端弹窗宽度与前台站点变量对齐，不依赖后台页面语义。
- 首页与顶部栏触发按钮保持各自尺寸，但使用相同焦点、悬停和可访问名称。

## 评论功能对齐

### 请求上下文与隐私

- `CommentRequestContext` 是 `createPublicComment` 的唯一环境参数类型。
- 所有服务调用方和测试统一传入 `ipAddress`、`ipCity`、`userAgentSummary`、`browserName`、`browserVersion`。
- 请求上下文仅由服务端请求头和 IP 城市查询生成，客户端 JSON 中伪造的环境字段无效。
- 私有、环回和链路本地 IP 不请求外部城市服务；查询失败降级为 `null`，不阻断评论。
- 数据库存储完整 IP 与 User-Agent 摘要供管理和排障使用；公开响应只包含 `avatarHash`、`browserName`、`browserVersion` 和 `ipCity`。

### 评论返回与前台状态

- `createPublicComment` 统一返回 `id`、`status`、`duplicate`、`comment`。
- 审核立即通过时 `comment` 为完整 `PublicComment`；待审核时为 `null`。
- 重复请求返回原评论状态，已公开评论同时返回原公开评论对象。
- 前台只在收到已批准的 `comment` 时即时插入列表，并按 ID 去重。
- 评论数量、空态、加载更多可见数量和回复目标随即时评论同步。
- 评论者昵称、邮箱和网站继续保存在本地浏览器；评论正文和蜜罐字段提交后清空。

### 头像与环境信息视觉

- 有 `avatarHash` 时请求 Gravatar，使用 `d=404` 让缺失头像进入本地回退。
- Gravatar 错误后显示稳定颜色的首字头像，不循环重试同一哈希。
- 浏览器与城市组成一条可选辅助信息；任一字段缺失时只显示存在部分，全部缺失时不渲染。
- 环境信息使用等宽小号文字并允许在窄屏换行，不挤压作者、日期和回复按钮。

## 数据库迁移对齐

- `0007_comment_client_context.sql` 为评论表增加 `ip_address`、`ip_city`、`browser_name`、`browser_version`。
- Drizzle Schema、迁移日志和运行时迁移测试统一为 8 个迁移。
- 运行时迁移测试同时验证四个新增字段、重复执行零迁移和外键完整性。
- 不修改已有迁移文件，不使用破坏性重建表操作。

## 与既有功能的兼容

- 后台评论列表继续使用管理员所需的邮箱字段，并补齐公开头像哈希和可显示环境信息。
- 前台页脚一言继续由浏览器按路径无缓存获取；关闭开关时才显示后台页脚文字。
- 后台 `admin-ui.css` 与前台 `globals.css` 分别保持职责，根布局显式加载两套样式，避免依赖 CSS 导入顺序。
- 搜索弹窗可以复用共享 Dialog 行为，但前台内容区域使用独立 `sora-*` 样式类。

## 测试与验收

### 自动化验证

- 搜索服务：空关键词、长度限制、公开内容过滤、前缀匹配、中文包含匹配和排序。
- 搜索 UI：防抖请求、结果展示、空态、错误态、关闭重置和请求取消。
- 评论上下文：代理 IP 顺序、私有 IP 跳过查询、浏览器解析、城市查询失败降级。
- 评论 API：客户端伪造字段被忽略、立即公开与待审核响应形状。
- 评论服务：环境字段写入、隐私字段不公开、重复请求、限流与审核设置。
- 评论 UI：Gravatar 回退、资料持久化、即时评论插入、计数更新、待审核提示和环境信息。
- 迁移：8 个迁移、四个新增字段、重复运行幂等、外键检查。
- 既有后台和页脚专项测试继续通过。

### 完整检查

1. 定向 Prettier 与 ESLint。
2. TypeScript 类型检查。
3. 全量 Vitest。
4. Next.js 生产构建。
5. 桌面与手机宽度浏览器冒烟验证：搜索弹窗、评论提交状态、头像回退、环境信息换行、后台核心页面。

## 完成标准

- 所有新增功能的生产接口、类型、调用方、迁移和测试使用同一契约。
- 新增前台组件与既有 Sora 视觉和响应式规则一致，无明显溢出或状态缺失。
- 自动化检查与生产构建通过；若浏览器验证受环境数据或外部服务限制，必须记录具体降级结果。
