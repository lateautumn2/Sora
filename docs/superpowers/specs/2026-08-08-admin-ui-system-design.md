# Sora 后台 UI 系统重构设计

## 背景

当前后台、登录页和初始化页主要依赖原生表单控件、零散的 `.form-input` 样式以及页面内自定义结构。Select、Checkbox、文件输入、错误提示和操作区缺少统一组件边界，导致不同页面的控件尺寸、交互状态、响应式行为和视觉层级不一致。

本次重构建立统一的后台 UI 系统，并同步整理整个后台的信息架构。业务数据模型、数据库结构、路由含义和既有权限边界保持不变。

## 目标

- 覆盖全部后台页面，以及登录和初始化页面。
- 统一 Input、Textarea、Select、MultiSelect、Checkbox、Switch、FileInput、Button、Dialog、Tabs、Tooltip、Toast、Field 和分页等基础组件。
- 统一页面标题、操作区、筛选区、内容区、表单分区、列表、空态、错误态和加载态。
- 保持圆角与阴影风格，以黑、白、灰构建层级，以 `#82045b` 作为品牌主色。
- 提供完整的键盘操作、焦点管理和 ARIA 状态。
- 保持现有业务能力，不借 UI 重构改变数据库或内容行为。

## 非目标

- 不修改数据库 Schema 或迁移历史。
- 不改变站点前台视觉体系。
- 不重写 Markdown 编辑器内核。
- 不增加后台实时协作、复杂权限或新的业务工作流。
- 不用完整 MUI 或 Ant Design 主题替换项目视觉。

## 已确认设计决策

| 项目 | 决策 |
| --- | --- |
| UI 技术 | Radix Primitives + Sora 本地组件层 |
| 页面范围 | 全部后台、登录和初始化页面 |
| 页面结构 | 控件、表单布局和后台信息架构一并重构 |
| 默认密度 | 40px 均衡密度；移动端触控目标不低于 44px |
| 基础配色 | 黑、白、灰 |
| 品牌主色 | `#82045b` |
| 外观 | 6-8px 圆角，分层阴影，克制边框 |
| 数据层 | 保持现有路由、服务和数据库契约 |

## 组件架构

新增 `components/ui/` 作为后台和认证页面共用的基础组件层。页面只能通过这些组件表达表单状态，不再直接复制输入框、下拉框或错误提示样式。

### 基础组件

- `Button`、`IconButton`：primary、secondary、ghost、danger 四种意图，以及 loading、disabled 状态。
- `Input`、`Textarea`：统一尺寸、占位符、自动填充、只读、禁用、错误和焦点状态。
- `Field`：组合 Label、必填标记、说明文字和字段错误，并生成稳定的可访问关联 ID。
- `Select`：基于 Radix Select，适用于数量较少的固定选项。
- `Combobox`：基于 Radix Popover 与可搜索命令列表，适用于分类等较长选项。
- `MultiSelect`：基于 Popover、搜索输入和 Checkbox，支持标签多选、键盘选择与移除。
- `Checkbox`：用于随表单提交的布尔值。
- `Switch`：用于启用、停用等即时状态。
- `FileInput`：统一点击选择、拖放、文件摘要、上传状态和错误反馈。
- `Dialog`、`ConfirmDialog`：统一创建、编辑、预览和危险操作确认。
- `Tabs`、`Tooltip`、`Toast`、`Pagination`：统一页面切换、图标说明、短反馈和分页。

Radix 只负责行为、焦点和无障碍语义。视觉样式、文案和页面组合全部保留在项目本地，避免形成通用框架模板外观。

### 依赖范围

计划引入必要的 Radix React primitives：Select、Popover、Checkbox、Switch、Dialog、Tabs、Tooltip、Label 和 Toast。可搜索选择列表使用 `cmdk`，图标继续使用项目已有的 Lucide React。

不引入 MUI、Ant Design、Emotion 或另一套主题运行时。

## 视觉系统

### 色彩

- 页面背景：浅灰；深色侧栏使用接近黑色的中性色。
- 内容表面：白色或极浅灰色。
- 正文与标题：分级黑灰色。
- 主操作、选中状态和焦点环：`#82045b`。
- 成功、警告、危险色只表达状态，不参与品牌装饰。
- 所有文字与交互状态满足可读对比度要求。

### 圆角与阴影

- 输入控件和按钮：6px 圆角。
- 内容面板、列表容器和 Dialog：8px 圆角。
- 普通内容面板使用低层级柔和阴影。
- Select、Popover 和菜单浮层使用中层阴影。
- Dialog 使用最高层阴影和遮罩。
- 页面分区保持完整布局，不把每个小字段包装成独立卡片，也不嵌套卡片。

### 密度与响应式

- 桌面端表单控件默认高度 40px。
- 移动端交互目标最小高度 44px。
- 紧凑列表可使用 36px 工具栏控件，但不得降低可操作性。
- 桌面表格在窄屏转为信息行或卡片列表，禁止横向溢出。
- Select、Popover 和 Dialog 必须限制最大尺寸并适配小屏。

## 后台信息架构

### 全局壳层

- 左侧主导航按“内容、互动、管理、系统”分组。
- 当前页面使用 `#82045b` 高亮。
- 顶栏只保留面包屑、必要的页面级状态和账号入口。
- 页面主体统一为：页面标题区、主要操作、可选 Tabs、筛选工具栏、内容区、分页。
- 移动端使用现有抽屉导航模式，但复用相同导航数据与选中状态。

### 页面映射

- 仪表盘：数据摘要、近期内容和系统状态；不恢复“新建文章”按钮。
- 文章和页面：状态 Tabs、搜索筛选、统一列表、分页与回收站。
- 评论：继续以文章为主体分组，组内展示评论线程、审核与删除操作。
- 分类与标签：统一管理结构；新建和编辑使用 Dialog；列表支持搜索和分页。
- 图片管理：上传区、筛选区、分页图库、图片预览 Dialog 和地址复制。
- 菜单与友链：数据列表配合新建/编辑 Dialog；启停使用 Switch；删除使用 ConfirmDialog。
- 设置：左侧分区导航，右侧单列表单，底部固定保存操作区。
- 文章编辑器：正文保持主区域；分类、标签、发布和 SEO 设置进入右侧设置面板；移动端改为底部或全屏设置面板。
- 登录与初始化：居中表单面板，复用同一套 Field、Input、Button 和错误提示。

## 表单与数据流

现有 Server Action、Zod 校验、权限检查和服务层继续作为业务事实来源。UI 层不得绕过 `requireAdminSession()` 或直接访问数据库。

表单提交采用统一的 `ActionState`：

- `status`: idle、submitting、success 或 error。
- `fieldErrors`: 按字段名返回可显示错误。
- `formError`: 页面级或不可归属到字段的错误。

客户端表单包装器使用 `useActionState` 展示 pending 状态并阻止重复提交。字段错误返回后聚焦第一个无效字段。成功后按页面需要选择原地 Toast、刷新当前数据或跳转；现有 URL notice 参数在迁移期间继续兼容。

无需即时反馈的 Server Component 保持服务端渲染。只有 Select、Combobox、Dialog、Toast、上传进度和需要本地状态的表单边界使用 Client Component。

## 交互规则

- 少量固定选项使用 Select。
- 分类等较长单选数据使用 Combobox。
- 标签使用 MultiSelect，支持搜索、选择、移除和清空。
- Checkbox 表示随表单保存的布尔值；Switch 表示即时启停。
- 新建和编辑轻量数据使用 Dialog；文章编辑继续使用独立页面。
- 删除统一使用 ConfirmDialog，危险操作按钮不得与主操作同色。
- 图标按钮使用 Lucide 图标并提供 Tooltip 与可访问名称。
- Popover 和 Dialog 关闭后必须把焦点返回触发器。
- Escape、Tab、方向键、Home 和 End 按对应 Radix 组件键盘模型工作。

## 页面状态

所有列表和表单必须覆盖：

- 初始加载或提交中状态。
- 空数据状态。
- 无搜索结果状态。
- 字段级校验错误。
- 页面级加载或服务错误。
- 成功反馈。
- 禁用与无权限状态。

错误信息必须说明可执行的下一步，不使用仅有颜色变化的错误提示。

## 迁移策略

1. 建立主题 Token、Tooltip/Toast 上下文边界和基础 UI 组件。
2. 用独立测试验证组件状态、键盘和表单值提交。
3. 迁移后台壳层、登录页和初始化页，建立统一页面模板。
4. 迁移编辑器、设置、分类、标签、菜单和友链等表单密集页面。
5. 迁移文章、页面、评论、图片管理和仪表盘等列表页面。
6. 删除不再使用的旧表单样式，仅保留前台确实使用的全局样式。

每一步保持可运行，避免一次性删除旧样式导致未迁移页面失效。

## 测试与验收

### 自动化验证

- UI 单元测试：组件状态、表单值、键盘、焦点回收、错误关联和禁用状态。
- 页面集成测试：设置保存、文章编辑、分类标签、菜单、友链、评论审核和图片上传。
- Playwright：登录、初始化、后台导航、主要增删改查、回收站和移动端关键流程。
- 静态验证：ESLint、TypeScript、Vitest、Prettier 聚焦检查和 Next.js 生产构建。

### 视觉验收

- 桌面端至少覆盖 1440x900。
- 移动端至少覆盖 390x844。
- 检查 Select 浮层、MultiSelect、Dialog、错误态、加载态和空态。
- 检查圆角与阴影层级一致，主色未被滥用。
- 检查文字不溢出、控件不跳动、页面无横向滚动和遮挡。

## 验收标准

- 后台、登录和初始化页面不再直接使用未封装的可见原生 Select、Checkbox 或重复表单样式。
- 所有可见表单控件来自 `components/ui/` 或经过该层封装。
- 全部后台页面遵循统一标题、工具栏、内容区和分页结构。
- 主色为 `#82045b`，其余视觉以黑白灰为基础。
- 页面保持 6-8px 圆角和三档阴影层级。
- 桌面和移动端关键路径可操作且无横向溢出。
- 既有业务测试通过，数据库结构和前台视觉没有非预期变化。
